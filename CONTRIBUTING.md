# Contributing

Keep changes focused on the throttle/brake overlay.

Use main for reviewed work and dev for ongoing implementation. Branch protection is not configured by this document.
Use small pull requests from dev or a focused topic branch. Do not merge a PR simply because its code compiles.

Before changing behaviour, read README.md, docs/REQUIREMENTS.md and AGENTS.md.
Update the requirements when scope changes and explain the user-visible effect in the PR.
Include relevant tests with implementation changes. Documentation-only changes need link, consistency and whitespace checks rather than a game build.

Record exactly what was tested and what remains untested. Screenshots made with synthetic data must say so.
Never commit credentials, personal game saves, captured telemetry, local logs or third-party game files.
